# ZURA — Обзор проекта (Русский)

## Что это такое

ZURA — это самодостаточный таск-менеджер для небольших команд и стартапов.
Идея проекта — сделать простую альтернативу Jira без лишней абстракции,
перегруженного интерфейса и корпоративного оверинжиниринга.

Проект запускается локально. Данные хранятся у тебя, а не в чужом облаке.

---

## Текущее состояние

Проект находится на начальном этапе. На данный момент реализована только
инфраструктура пользователей и компаний. Самого таск-менеджера ещё нет.

### Что уже работает

- Регистрация и авторизация (JWT)
- Два типа пользователей:
  - **SEO-пользователь** — владелец компании, может нанимать сотрудников
  - **Сотрудник** — обычный участник команды
- Управление компанией (создание при регистрации)
- Управление сотрудниками (найм, редактирование, удаление)
- Отделы и роли (QA, Development, DevOps, Design и т.д. — ~60 ролей)
- Смена пароля, редактирование профиля
- API-документация (Swagger / ReDoc)

### Чего ещё нет

- Задачи (tasks) — основная фича
- Проекты / доски
- Статусы задач, приоритеты, назначение
- Комментарии, вложения
- Уведомления
- Поиск и фильтрация

## Технологический стек

| Слой         | Технология                        |
|--------------|-----------------------------------|
| Backend      | Django + Django REST Framework    |
| Авторизация  | JWT (SimpleJWT)                   |
| База данных  | PostgreSQL                        |
| Frontend     | React 19 + TypeScript             |
| Сборка       | Vite                              |
| Роутинг      | React Router                      |
| HTTP-клиент  | Axios (с авто-обновлением токена) |
| Стейт        | React Context + TanStack Query    |

## Ключевые решения

- **Email вместо username** — логин по почте, никакого username
- **Stateless-авторизация** — JWT в localStorage, без серверных сессий
- **SEO-пользователь** — первый зарегистрированный в компании автоматически
  становится владельцем и получает расширенные права
- **Атомарное создание компании** — компания создаётся в одной транзакции
  вместе с пользователем

## Что стоит решить перед развитием проекта

Перед тем как двигаться вперёд, хорошо бы ответить на эти вопросы:

1. **Структура задач** — что такое задача? Какие у неё поля?
   (название, описание, статус, приоритет, исполнитель, дедлайн, тип?)

2. **Модель проектов** — задачи живут внутри проектов или напрямую в компании?

3. **Доски** — нужен Kanban? Scrum? Или просто список?

4. **Права доступа** — кто может создавать, редактировать, закрывать задачи?
   Только владелец? Любой сотрудник?

5. **Хранение токенов** — localStorage небезопасен для продакшна.
   Рассмотреть httpOnly-куки?
